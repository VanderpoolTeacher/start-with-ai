Build a Hook

Last week you gave Claude a skill. Today you give it a habit — something that runs on its own.

The setup

Those recap decks today? Nobody asked for them.

Claude finished a big task, and a slide deck just… appeared. A hook made it.

What it is

A hook is a command tied to an event.

  • Skill — runs when you ask
  • Hook — runs on its own, when something happens

Today's event: Stop — the moment Claude finishes.

Where they live

One file: ~/.claude/settings.json

{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command",
        "command": "bash ~/.claude/hooks/done.sh" } ] }
    ]
  }
}

Read it plainly: on Stop, run done.sh.

Your real one

Every hook has the same shape.

# 1 — should I act? check first.
[ -e "$sentinel" ] && exit 0        # already ran
[ "$tool_calls" -ge 25 ] || exit 0     # not much happened

# 2 — if yes, act.
echo '{"decision":"block","reason":"...build a recap deck..."}'

Check, then act. Yours today skips the checks and goes straight to acting.

Try it — 15 minutes

Write a hook that logs every time Claude stops.

# ~/.claude/hooks/done.sh
#!/usr/bin/env bash
echo "Claude finished at $(date)" >> ~/claude-done.log
exit 0
  • then chmod +x ~/.claude/hooks/done.sh
  • then add the Stop hook to settings.json
  • then ask Claude anything, and watch it stop

Done looks like

Proof it fired.

$ cat ~/claude-done.log
Claude finished at Tue Aug 18 15:41:02 EDT 2026
Claude finished at Tue Aug 18 15:43:19 EDT 2026

Two triggers, two lines. Empty file? That's normal the first time — we fix it next.

Check · answers

A hook needs three things to run.

  • The path is right use the real path, not ~
  • The script is executable chmod +x
  • The JSON is valid one missing comma = ignored
